# Receipt Generator Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a two-outlet receipt generator with editable Malaysia date, no numbering, and downloadable/printable receipts.

**Architecture:** Extend the existing buildless GitHub Pages app. A pure receipt model validates inputs and calculates integer-sen totals; separate HTML and canvas/PDF renderers consume that model, while a small UI module binds the form. No backend or persistence.

**Tech Stack:** ES modules, HTML/CSS, Node built-in tests, vendored pdf-lib 1.17.1, browser Canvas.

**Spec:** docs/superpowers/specs/2026-10-30-receipts-design.md

## Global Constraints

- No receipt numbers, numbering counters, database, sign-in, or shared history.
- Date defaults to the generation date in Asia/Kuala_Lumpur; staff may override.
- Required client name, optional phone/email, one or more described items.
- Prices exclude SST; show subtotal, SST (8%), and total in MYR.
- Customer details remain in memory and downloaded files only.
- Same-tab tool navigation and existing heater/gallery behavior remain intact.
- Native execution in the existing feature checkout; publication is already authorized by the website request.

## Review Focus

- A form open across Malaysia midnight must use today's date unless manually overridden.
- Decimal prices and multiple quantities must not accumulate floating-point tax errors.
- Malicious markup and multilingual names must render as text in preview and PDF.
- Long client details and many item rows must not overwrite totals or page footers.
- A failed export must preserve the form and re-enable export actions.

### Task 1: Receipt model and date behavior

**Files:** create assets/receipt.js and tests/receipt.test.js.

**Interfaces:** `outlets` holds the two legal identities; `malaysiaDate(now = new Date())` returns YYYY-MM-DD; `resolveReceiptDate(value, manual, now)` selects the overridden or automatic date; `buildReceipt(draft)` returns normalized client/outlet/date/items plus subtotalSen, taxSen, totalSen; `formatMoney(sen)` returns a two-decimal amount; errors expose a field key for focusing invalid inputs.

Assert RM100 -> tax RM8 and RM108 total; 3 x RM0.10 + RM0.01 -> subtotal31/tax2/total33 sen; both legal identities and absent optional contacts survive normalization.
- [ ] Run `node --test tests/receipt.test.js`; confirm missing behavior fails.
- [ ] Implement the pure model with strict decimal-to-sen parsing and round-half-up total SST.
- [ ] Test automatic Malaysia dates at 15:59:59Z / 16:00:00Z with literal expected 2026-10-30 / 2026-10-31, and manual override preservation. Run full `npm test`.

### Task 2: Receipt presentation and PDF generation

**Files:** create assets/receipt-view.js, assets/receipt-pdf.js, assets/vendor/pdf-lib-1.17.1.js and LICENSE; tests/receipt-view.test.js.

**Interfaces:** `receiptMarkup(receipt)` returns escaped semantic receipt HTML with no number; `createReceiptPdf(receipt)` returns Uint8Array; `receiptFilename(receipt)` returns a safe descriptive PDF filename. Both consume Task 1's normalized model. PDF uses sequential 3x A4 canvas pages and embeds each raster into pdf-lib; wrapping measures actual text width.

- [ ] Write failing tests that rendered output includes correct outlet/date/totals, omits absent contacts, escapes literal HTML in user fields, and preserves Unicode. Test filename sanitization without leaking unsafe path characters.
- [ ] Run tests, implement presentation, vendor the pinned local library and license, implement multipage PDF layout with repeated outlet/date and final subtotal/tax/total block.
- [ ] Verify tests pass. Browser-driven export will validate the actual PDF and long/multilingual layout in Task 3.
